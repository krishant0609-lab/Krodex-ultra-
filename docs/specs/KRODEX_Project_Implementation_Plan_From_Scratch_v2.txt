                         KRODEX
      PROJECT IMPLEMENTATION PLAN

       From-Scratch Engineering Roadmap · Dependency-Gated Delivery · Verification-First
       PRD  TRD  Flow  UI/UX  Implementation  Schema  Core  Intelligence

                                            Version 2.0 · September 2026

Gate  Build focus                                           Exit condition
G0    Vision, PRD, TRD, flow, UI/UX                         Requirements frozen and traceable
G1    Schema + persistence                                  Migrations, constraints and tests green
G2    Services + APIs                                       Business rules and API contracts green
G3    Events + jobs                                         Idempotent event propagation verified
G4    Analytics + student model                             Metrics reproducible from evidence
G5    Frontend integration                                  Every route uses real APIs and states
G6    UI/UX + motion                                        Visual acceptance + accessibility
G7    AI layer                                              Grounded, authorized, failure-safe
G8    Production readiness                                  Security, performance, E2E and deployment checks

The implementation order is intentionally dependency-first. Do not start with visual polish or AI while the durable state and business
rules are unstable. The objective is a real application whose UI is a truthful projection of the backend.

Phase 0 -- Repository & Environment Reset

Start from the deleted-app state and establish a reproducible foundation.

Work package

 · Initialize the framework, package manager and TypeScript configuration.
 · Define environment-variable contract and safe local defaults.
 · Create formatting/lint/typecheck/test/build scripts.
 · Set up Git, branch strategy and commit conventions.
 · Create docs/architecture and decision records.

Engineering guardrails

 · No feature code before architecture acceptance.
 · Never commit secrets.
 · Local development must be reproducible from clean install.
 · Build and test commands must be documented.

Verification gate

Exit: clean install  typecheck  lint  tests  build succeeds on an empty application shell.

Definition of Done

 · Code is type-safe and lint-clean under the project's configured toolchain.
 · Automated tests cover the new behavior and important failure paths.
 · No fake data or UI-only state is used to represent a backend fact.
 · The feature is observable through its source record/event/evidence where applicable.
 · Documentation and migration notes are updated before the phase closes.

Dependencies

This phase may consume outputs from earlier phases, but it must not bypass their contracts. If an upstream contract is insufficient,
stop and revise that contract rather than adding an ad-hoc client-side workaround.

Critical Automated Journeys

These are the product's most important tests.

Area  Implementation requirement
J1    Wrong Test answer automatically creates Error evidence and snapshot.
J2    Error Review incorrect keeps Error active and adds recurrence.
J3    Qualifying Review correct resolves Error.
J4    Later wrong answer reopens the same Error pattern.
J5    Custom Test from 20 selected Errors contains exactly the intended pool.
J6    Planner miss creates recovery/backlog pressure and updates progress evidence.
J7    Completed backlog recovery improves relevant analytics without erasing history.
J8    Dashboard/Insights/Notifications converge after each domain event.
