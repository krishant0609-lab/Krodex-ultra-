1. Schema Principles

The schema must support the complete KRODEX learning loop and preserve historical truth.

Schema contract

 · Every student-owned record is isolated by student/account ownership.
 · Historical evidence is append-only wherever the record represents an observation.
 · Current lifecycle state is constrained by explicit transitions.
 · Foreign keys preserve cross-entity integrity.
 · Derived metrics are not the primary source of truth.

Engineering rule

Schema changes are reviewed against PRD behavior, TRD contracts and App/Web Flow consequences.

Verification

 · The rule has an automated test or a clearly defined test scenario.
 · The relationship cannot be bypassed by normal API calls.
 · Historical evidence remains available after downstream state changes.
 · A migration or seed change is reproducible from a clean database.
